# TeamFinder

Итоговый Django-проект для поиска команды и совместной работы над pet-проектами.

По умолчанию проект настроен на **вариант 1** (`TASK_VERSION=1`): избранное и фильтрация пользователей. Поддержка вариантов 2 и 3 тоже сохранена и переключается через `.env`.

## Что реализовано

- регистрация и вход по email;
- публичные профили пользователей;
- редактирование профиля и смена пароля;
- список пользователей с пагинацией по 12 карточек;
- список проектов с пагинацией по 12 карточек;
- создание, редактирование и завершение проекта;
- участие в чужих проектах;
- добавление проектов в избранное и отдельная страница избранного;
- PostgreSQL и запуск через Docker Compose;
- демонстрационные данные для ревьюера;
- админ-панель Django;
- базовые автотесты и GitHub Actions CI.

## Структура вариантов

Значение `TASK_VERSION` в `.env` определяет, какой комплект шаблонов используется:

- `TASK_VERSION=1` — избранное и фильтрация пользователей;
- `TASK_VERSION=2` — навыки пользователей и фильтрация пользователей по навыкам;
- `TASK_VERSION=3` — навыки проектов и фильтрация проектов по навыкам.

Для проверки этой работы основным считается **вариант 1**.

## Быстрый запуск для ревьюера

### 1. Подготовить `.env`

Скопируйте пример файла:

```bash
cp .env_example .env
```

В `.env_example` уже указаны рабочие значения для запуска через Docker. Для проверки текущей работы оставьте:

```env
TASK_VERSION=1
```

### 2. Запустить проект

```bash
docker compose up --build
```

После запуска проект будет доступен по адресу:

```text
http://127.0.0.1:8000/projects/list/
```

Если порт `8000` на компьютере уже занят другим локальным сервером, можно временно изменить маппинг порта для сервиса `web` в `docker-compose.yml`, например на `8001:8000`, и открыть `http://127.0.0.1:8001/projects/list/`.

База данных PostgreSQL поднимется в отдельном контейнере. Данные сохраняются в Docker volumes:

- `postgres_data` — база данных;
- `media_data` — пользовательские медиафайлы.

### 3. Остановить проект

```bash
docker compose down
```

Если нужно остановить и удалить volumes:

```bash
docker compose down -v
```

## Что проверить ревьюеру

### Общий функционал

- главная страница: `/projects/list/`
- список пользователей: `/users/list/`
- страница избранного: `/projects/favorites/`
- страница пользователя: `/users/<id>/`
- страница проекта: `/projects/<id>/`
- регистрация: `/users/register/`
- вход: `/users/login/`
- редактирование профиля: `/users/edit-profile/`
- смена пароля: `/users/change-password/`

### Основной сценарий проверки (вариант 1)

1. Войти под `anna@example.com` / `Teamfinder123`.
2. Открыть `/projects/list/`.
3. Добавить любой чужой проект в избранное.
4. Открыть `/projects/favorites/` и проверить, что проект появился.
5. Открыть чужой проект и присоединиться к нему.
6. Открыть `/users/list/` и проверить 4 фильтра:
   - `owners-of-favorite-projects`
   - `owners-of-participating-projects`
   - `interested-in-my-projects`
   - `participants-of-my-projects`
7. Открыть свой профиль и проверить редактирование профиля.
8. Создать новый проект.
9. Отредактировать созданный проект.
10. Завершить созданный проект.
11. Проверить `/admin/`.

### Проверка других вариантов

#### Вариант 2

Поставьте в `.env`:

```env
TASK_VERSION=2
```

Проверьте:

- блок навыков на странице владельца профиля;
- добавление и удаление навыков без перезагрузки;
- фильтр пользователей по навыкам на `/users/list/`.

#### Вариант 3

Поставьте в `.env`:

```env
TASK_VERSION=3
```

Проверьте:

- блок необходимых навыков на странице проекта;
- добавление и удаление навыков проекта без перезагрузки;
- фильтр проектов по навыкам на `/projects/list/`.

## Локальный запуск без Docker

Этот вариант не нужен ревьюеру, но удобен для разработки.

### 1. Создать виртуальное окружение

```bash
python -m venv .venv
```

На Windows:

```bash
.venv\Scripts\activate
```

На Linux/macOS:

```bash
source .venv/bin/activate
```

### 2. Установить зависимости

```bash
pip install -r requirements.txt
```

### 3. Подготовить `.env`

```bash
cp .env_example .env
```

Если PostgreSQL запускается локально вне Docker, укажите свои параметры подключения.

### 4. Применить миграции и создать демо-данные

```bash
python manage.py migrate
python manage.py seed_demo
```

### 5. Запустить сервер

```bash
python manage.py runserver
```

## Полезные команды

Проверка тестов:

```bash
python manage.py test
```

Создание миграций:

```bash
python manage.py makemigrations
```

## Технические детали

- Framework: Django 5
- Database: PostgreSQL
- Containerization: Docker Compose
- Хранение данных БД: volume `postgres_data`
- Хранение медиафайлов: volume `media_data`
